# PRD:基于 AI Agent 的旅行助手

> 对应简历项目经历「基于 AI Agent 的旅行助手」的产品文档体系。
> 本文档为该项目在本仓库中的工程化落地版本。

## 1. 背景与问题

大学生等群体在假期存在「犹豫去哪里旅行、不会做行程、预算难控制」的痛点:
- 信息分散:攻略散落在小红书/微博/公众号,检索成本高;
- 决策链路长:定目的地 → 查交通 → 查景点 → 查美食 → 查住宿 → 算预算,环节割裂;
- 经验依赖:没有踩坑经验,预约、交通、天气等风险意识弱。

## 2. 产品目标

- 用户输入一句自然语言(目的地/日期/偏好),产出**可执行的多日行程**:
  每日景点、餐饮、酒店、预算;
- 先做**可行性评估**(天气/季节/人流/预算),再给建议,减少「行程落地时翻车」;
- 知识库(RAG)驱动回答,尽量基于真实案例数据,提升准确度与可解释性。

## 3. 用户画像

| 画像 | 典型需求 | 关键点 |
| --- | --- | --- |
| 大学生(2-4人结伴) | 便宜、网红、拍照 | 预算敏感,偏好经济型住宿 |
| 上班族情侣(周末/小长假) | 省心、品质、出片 | 时间紧,要「落地即玩」 |
| 亲子家庭 | 安全、节奏慢、亲子设施 | 需要备选方案 |

## 4. 核心流程(与实现一一对应)

```
用户输入/语音识别 → LLM 理解 → RAG 检索 → 可行性评估 → 旅行建议生成
        └──(信息不足)→ 澄清追问
```

| 环节 | 实现 | 位置 |
| --- | --- | --- |
| LLM 理解 | 需求解析结构化 JSON(目的地/日期/天数/预算/偏好) | `app/agent/nodes.py: parse_node` |
| RAG 检索 | 旅行案例知识库向量检索(城市软过滤+相关度阈值) | `app/rag/retriever.py` |
| 可行性评估 | 天气工具(Open-Meteo)+ 预算测算 + 知识库季节建议 | `app/agent/nodes.py: evaluate_node` |
| 旅行建议生成 | DeepSeek 生成 Markdown 行程(可绑定高德/天气工具) | `app/agent/nodes.py: generate_node` |

## 5. 功能需求

### 5.1 功能清单(本版本落地)

| 编号 | 功能 | 说明 | 优先级 |
| --- | --- | --- | --- |
| F1 | 自然语言需求理解 | 解析目的地/日期/天数/预算/偏好 | P0 |
| F2 | RAG 智能问答 | 基于旅行案例知识库的回答 | P0 |
| F3 | 行程生成 | 每日景点/餐饮/住宿/预算 Markdown | P0 |
| F4 | 可行性评估 | 天气预报+季节+人流+预算测算 | P1 |
| F5 | 高德地图工具 | 地址编码/POI 搜索/周边查询 | P1 |
| F6 | 澄清追问 | 缺少目的地/天数时反问 | P1 |
| F7 | 交互界面 | CLI + Streamlit 原型 | P2 |

### 5.2 未来迭代(roadmap)

- 语音输入(接入 ASR)与语音播报(TTS)
- 图片识别(上传攻略截图 → 识别景点)
- MCP 协议接入高德(当前为 REST function-calling,与 MCP 等价语义)
- 多轮对话记忆与行程修订(长短期记忆)
- 用户画像沉淀(偏好学习)

## 6. 非功能需求

- 准确度:知识库优先引用,禁止臆造价格;检索召回信噪比通过 chunk 粒度控制
- 可用性:未配置 API Key 时可演示(mock 模式);工具故障自动降级
- 数据安全:密钥仅存 `.env`(gitignore),本地向量库持久化
- 可维护性:分层架构(LLM/RAG/Tools/Agent/UI),配置集中化
